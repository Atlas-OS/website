This page explains each security setting Atlas lets you change, what it protects and which file changes it.
Read it before you turn any protection off.

The files are in <CodeInline text="7. Security" /> in the Atlas folder, at <CodeInline text="%windir%\AtlasDesktop" />.

<Callout type="danger" title="Understand the risk">
  Turn off a protection only if you know what it protects and how you'll protect your PC without
  it. Turning protection off can expose your files, accounts and PC to attack.
</Callout>

## Defender

Microsoft Defender is the antivirus built into Windows.
It protects against threats such as ransomware and spyware.
Atlas recommends keeping it.

During installation, Atlas Manager asks **Keep Microsoft Defender?**, with two answers:

- **Keep Microsoft Defender (recommended)** keeps Windows' antivirus.
- **Remove Microsoft Defender** removes it, along with SmartScreen. Your PC has no antivirus protection until you install another antivirus app, and Windows doesn't warn you before you open unrecognised apps or downloads.

Whichever you choose, Atlas turns off Smart App Control, Enhanced Phishing Protection and Find my device.

This choice is separate from the Windows Security step during installation.
In that step, you turn off the four Windows Security protection switches so they don't block installation.
If you keep Defender, turn those switches back on after installation; Atlas Manager reminds you if any is still off.

If you use another trusted antivirus app, you don't need to remove Defender.

### Change Defender later

In <CodeInline text="7. Security" /><IconArrow /><CodeInline text="Defender" />, run <CodeInline text="Toggle Defender.cmd" /> and choose **Disable Windows Defender** or **Enable Windows Defender**.
Restart when it asks.
After enabling Defender, open Windows Security and check that the protection switches are on; bringing Defender back doesn't turn every switch on.

When you update or reinstall Atlas, **Choose again** also lets you keep or remove Defender.

### Windows Security page and tray icon

Two subfolders of <CodeInline text="Defender" /> change how Windows Security looks:

- <CodeInline text="Hide App and Browser Control" />: <CodeInline text="Hide App and Browser Control (default).cmd" /> hides the **App & browser control** page in Windows Security, and <CodeInline text="Show App and Browser Control.cmd" /> shows it.
- <CodeInline text="Security Health Tray" />: <CodeInline text="Remove Security Tray from Startup (default).cmd" /> stops the Windows Security icon starting with Windows, and <CodeInline text="Add Security Tray to Startup.cmd" /> adds it back.

## Mitigations

Processor protections, also called security mitigations, defend against processor flaws such as Spectre and Meltdown, and against attacks that exploit bugs in apps.
They help stop a vulnerable app or game being used to run code on your PC.

During installation, Atlas Manager asks **Keep Windows' processor protections?**:

- **Keep processor protections (recommended)** keeps the Windows defaults.
- **Turn off processor protections** turns them off, along with Exploit protection for apps, such as Control Flow Guard. This reduces security. Any performance difference depends on your processor; on some recent processors, such as [AMD Zen 4](https://www.phoronix.com/news/AMD-Zen-4-Mitigations-Off), turning them off reduces performance.

To change the choice later, open <CodeInline text="7. Security" /><IconArrow /><CodeInline text="Mitigations" />, run one of these files, then restart:

- <CodeInline text="Set Windows Default Mitigations.cmd" /> restores the Windows defaults. It matches **Keep processor protections (recommended)**. Run it if an anti-cheat stops working after you turn protections off.
- <CodeInline text="Disable All Mitigations.cmd" /> turns them off. It matches **Turn off processor protections**.
- <CodeInline text="Enable All Mitigations.cmd" /> turns on every available protection. This is stricter than the Windows default and can reduce performance or compatibility.

### Fault Tolerant Heap

[Fault Tolerant Heap](https://learn.microsoft.com/windows/win32/win7appqual/fault-tolerant-heap) (FTH) applies extra protections to apps that keep crashing, at a cost to their performance.
Atlas turns it off.

In <CodeInline text="Mitigations" /><IconArrow /><CodeInline text="Fault Tolerant Heap" />:

- <CodeInline text="Disable FTH (default).cmd" /> turns FTH off.
- <CodeInline text="Enable FTH.cmd" /> turns it on. Try it if an app keeps crashing.
- <CodeInline text="Reset FTH entries.lnk" /> clears the list of apps FTH is tracking.

Restart after turning FTH on or off.

## Core isolation

[Core isolation](https://support.microsoft.com/windows/core-isolation-e30ed737-17d8-42f3-a2a9-87521df09b78) uses virtualisation-based security (VBS) to run core parts of Windows in an isolated environment, out of reach of malicious software.
It can have a [noticeable performance cost](https://www.tomshardware.com/news/windows-11-gaming-benchmarks-performance-vbs-hvci-security), especially on older processors.

During installation, the check box **Turn off virtualisation-based security (VBS)** turns off VBS and memory integrity.
The check box starts ticked.
This removes an extra layer of Windows security.
Atlas leaves Credential Guard, LSA protection and kernel stack protection preferences as they are.

Games that use some anti-cheats, such as Riot Vanguard and FACEIT, may not start until you turn memory integrity back on with <CodeInline text="Enable VBS.cmd" />.
Riot explains this in [Error VAN: RESTRICTION: 5](https://support.riotgames.com/en-us/riot/penalties/error-van-restriction-5), and FACEIT in [Enabling Memory Integrity (HVCI)](https://support.faceit.com/hc/en-us/articles/8546882512284-Enabling-Memory-Integrity-HVCI).

In <CodeInline text="7. Security" /><IconArrow /><CodeInline text="Core Isolation (VBS)" />:

- <CodeInline text="Current Configuration.cmd" /> shows which core isolation features are available and running.
- <CodeInline text="Disable VBS.cmd" /> turns VBS and memory integrity off. It matches **Turn off virtualisation-based security (VBS)**.
- <CodeInline text="Enable VBS.cmd" /> turns them back on.
- <CodeInline text="Core Isolation - Windows Security.url" /> opens the **Core isolation** page in Windows Security.

Restart after either change.
A policy on your PC, or a UEFI lock, can keep VBS as it is; Atlas then leaves it unchanged and says why.

### Core isolation features

The features available depend on your hardware and firmware.

- **Memory integrity**, also called hypervisor-protected code integrity (HVCI), stops untrusted code from loading into the core of Windows.
- **Credential Guard** stops attackers stealing sign-in secrets from the Local Security Authority (`lsass.exe`).
- **Microsoft Vulnerable Driver Blocklist** blocks drivers with known security flaws.
- **Firmware protection** protects against compromised firmware.
- **Memory access protection**, also called Kernel DMA Protection, blocks malicious devices, such as those connected through Thunderbolt, from reading memory.
- **Kernel-mode Hardware-enforced Stack Protection** protects against [return-oriented programming](https://en.wikipedia.org/wiki/Return-oriented_programming) attacks.

## UAC

User Account Control (UAC) asks for permission before an app makes changes that need administrator rights.
Atlas Manager's **User account** check requires UAC to be on, and Atlas doesn't install from the built-in Administrator account.
Atlas has no file to turn UAC off.

Atlas changes one UAC setting during installation: UAC prompts don't switch to the secure desktop, so the screen doesn't dim.
The secure desktop stops software without administrator rights from imitating the prompt or interacting with it.
Without it, UAC prompts appear on the normal desktop, where other apps can draw over them or read credentials you type.

Windows' own UAC settings stay available in **Control Panel**<IconArrow />**User Accounts**<IconArrow />**Change User Account Control settings**.

## Firewall

Atlas keeps Windows Defender Firewall on, and has no file to turn it off.
It changes two groups of firewall rules:

- It turns off the Remote Assistance rules during installation, because Atlas turns off Remote Assistance.
- [File sharing](/docs/atlas-configuration/settings/#file-sharing) manages the File and Printer Sharing and Network Discovery rules. Atlas turns them off on a first installation. Turning file sharing on can enable them for Private networks only.
