This guide is for anyone who wants to improve Atlas.
Choose a project, make a focused change and submit it through GitHub.

## Our contribution platform

Atlas manages code, documentation, issues and reviews on [GitHub](https://github.com/Atlas-OS).
If you haven't used Git or GitHub before, complete the [GitHub quick-start guide](https://docs.github.com/get-started/quickstart) first.

Read the [Code of Conduct](https://github.com/Atlas-OS/.github/blob/main/CODE_OF_CONDUCT.md) before contributing.

## How to make changes

<Callout type="tip" title="Not sure whether people will like your change?">
  Propose it in [Discord](https://discord.com/invite/atlasos) or [GitHub
  issues](https://github.com/Atlas-OS/Atlas/issues) first. Mistakes are fine: reviewers give
  feedback in pull requests, and you don't need to get everything right first time.
</Callout>

Follow these steps to contribute:

1. **Fork or branch:** create a fork if you're an external contributor, or a branch if you're a team member.
2. **Make your changes:** keep each pull request to one fix or improvement.
3. **Submit a pull request:** open it against the primary branch.
4. **Wait for reviews:** external contributions need at least two reviews, and team members' need one.
5. **Merge:** after approval, a maintainer squash-merges the pull request into one commit.

<Callout type="info">
  Team members may skip pull requests for uncontroversial, well-tested changes that don't need
  review.
</Callout>

## Before you submit

- Match the repository's formatting and house style.
- Check grammar and spelling. Atlas documentation and interface copy use British English.
- In the Atlas repository, run the checks in the [contributor quick start](https://github.com/Atlas-OS/Atlas/blob/main/.github/CONTRIBUTING.md) and the [testing reference](https://github.com/Atlas-OS/Atlas/blob/main/docs/testing.md) that cover your change.

## Commit signature verification

Set up [commit signature verification](https://docs.github.com/en/authentication/managing-commit-signature-verification) so your commits show as **Verified**.
See this [guide to verified commits](https://gist.github.com/Beneboe/3183a8a9eb53439dbee07c90b344c77e#file-how-to-setup-verified-commits-md).

## Conventional commits

Use [Conventional Commits](https://www.conventionalcommits.org/) in Atlas repositories, in the form `type(scope): summary`.
Write the summary in the imperative and in lower case, without a full stop.

_Example_: <CodeInline text="fix(toggles): check the active power plan in Atlas health" />
