# Contributing to documentation

Use this guide to edit and preview the Atlas documentation locally. Read the [contribution guide](/docs/contributing/) first.

Fork [Atlas-OS/website](https://github.com/Atlas-OS/website), then clone your fork with `git clone https://github.com/YOUR_USERNAME/website.git`. Replace `YOUR_USERNAME` with your GitHub username.

## How the documentation is built

The Atlas documentation is built with [Astro](https://docs.astro.build/), using MDX for content. The docs live in <CodeInline text="src/content/docs/" /> and use:

- MDX files with frontmatter (title, metaDescription, order, etc.)
- Astro components for UI elements (Callout, CodeInline, Term, QuickLinkCard, etc.)
- A content collection schema defined in <CodeInline text="src/content.config.ts" />

<Callout type="tip">
  Keep the [Astro documentation](https://docs.astro.build/) and [MDX documentation](https://mdxjs.com/) open while you work.
</Callout>

## Prerequisites

The website requires [Bun](https://bun.sh/) (≥ 1.3.0) or [Node.js](https://nodejs.org/) (≥ 22.12.0). Bun is the recommended package manager.

## Preview your changes

The development server refreshes the page when you save a file.

1. Install dependencies: <CodeInline text="bun install" /> (or <CodeInline text="npm install" />)
2. Start the development server: <CodeInline text="bun dev" /> (or <CodeInline text="npm run dev" />)
3. Navigate to the URL shown in the console (typically <CodeInline text="http://localhost:4321" />)
4. Open <CodeInline text="/docs" /> to view the documentation

## Writing style

**Terminology:** Use "AtlasOS" for the product name in formal contexts (e.g., "AtlasOS documentation", "What is AtlasOS?"). Use "Atlas" for action-oriented titles (e.g., "Install Atlas", "Upgrade Atlas") and casual body text (e.g., "Atlas is for enthusiasts", "the Atlas folder"). Both are correct; the index establishes "AtlasOS (also called Atlas)".

**Content guidelines for readability:**

- **Lead with the action** - Write "Open Settings" instead of "Settings can be opened."
- **Address the reader** - Use "you" in guidance. Do not refer to "the user."
- **Use direct labels** - Link text and headings must name their destination or action.
- **Short paragraphs** - Aim for ~50 words or fewer per paragraph. One main idea per paragraph.
- **Use lists** - When you have 3 or more related items, use a bulleted or numbered list instead of a dense paragraph.
- **Break long pages** - Add a horizontal rule (<CodeInline text="---" />) or <CodeInline text="SectionDivider" /> between major sections to create visual breathing room.
- **Progressive disclosure** - For long reference lists (e.g., settings, options), use the <CodeInline text="Details" /> component so readers can expand only what they need.
- **Jargon** - Use the <CodeInline text="Term" /> component for technical terms. It shows a dotted underline; readers hover to see the definition.
